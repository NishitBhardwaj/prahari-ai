# Karnataka Police AI-Driven Crime Analytics Dataset

This repository contains the enterprise-scale synthetic dataset generated by the **Crime Simulation Laboratory**. The dataset is engineered specifically for the Karnataka Police AI-Driven Crime Analytics & Visualization Platform and provides production-grade, highly correlated relational, geospatial, graphical, and unstructured data suitable for AI training, graph analytics, RAG applications, and predictive intelligence.

---

## 1. Dataset Architecture

The dataset is generated through an event-driven, 25-engine Simulation Pipeline. Rather than randomly inserting independent records, the pipeline simulates realistic geographic scenarios, demographic behaviors, organized crime dynamics, financial transfers, and a comprehensive 13-step legal and investigative case lifecycle.

The data exported by the generator is fully formatted for seamless ingestion into modern data stacks:
*   **Relational Storage**: Standard `.csv` format (Ideal for PostgreSQL)
*   **Graph Storage**: Explicit edge lists in `.json` and `.csv` formats (Ideal for Neo4j APOC ingestion)
*   **AI Training & ML Targets**: Pre-joined and labeled `.parquet` datasets (Ideal for Pandas/PySpark ML pipelines)
*   **Unstructured Storage**: `.pdf`, `.jpg`, and `.png` generated media assets.

## 2. Included Data Models & Domains

### 2.1 Core Entities & Master Data
- **Jurisdictional Master**: Districts, Subdivisions, and Police Stations based geographically in Karnataka.
- **Legal Framework**: True-to-life mapping of Crime Heads to IPC and BNS Acts/Sections, dynamically adjusted based on the year of occurrence.
- **Population & Households**: Synthetic demographic networks mapping individuals to households, occupations, and district-level geographies.
- **Police Personnel**: Realistic police ranks and investigating officers assigned to specific stations and cases.

### 2.2 Case & Investigation Lifecycle
- **Dynamic Case Engine**: Simulates crimes factoring in weather, cultural festivals, demographics, and temporal multipliers (e.g., higher theft rates during festivals or at night).
- **13-Step Investigation Timeline**: Every crime follows a procedural event log:
  1. Complaint Registration
  2. FIR Assignment
  3. Investigating Officer (IO) Dispatch
  4. Crime Scene Spot Panchnamas
  5. Physical/Digital Evidence Collection
  6. Witness Interviews
  7. CCTV Procurement
  8. Phone/Tower Dumps (CDRs)
  9. Financial Freezes
  10. Suspect Identification
  11. Arrest Operations
  12. Chargesheet Filings
  13. Multi-Stage Court Proceedings (Hearings, Judgements)

### 2.3 Knowledge Graph & Link Analysis
Live graphical structures are maintained throughout the simulation, linking entities natively without relying purely on SQL joins:
- `Accused -> MEMBER_OF -> Gang`
- `Person -> OWNS -> Vehicle`
- `Person -> OWNS_ACCOUNT -> Bank Account`
- `Person -> CALLS -> Person` (Derived from dense Call Detail Records)
- `Person -> TRANSACTS_WITH -> Person` (Capturing Hawala operations and Cyber Frauds)
- `Evidence -> COLLECTED_IN -> Case`

### 2.4 Narrative & Textual Consistency (RAG Ready)
The simulation synthesizes distinct but factually aligned documents generated from a single "Master Incident Fact Sheet" to avoid hallucinations in downstream NLP processing:
- **Complaints**: Emotionally driven first-person accounts.
- **FIR Narratives**: Formal, structured third-person police terminology.
- **Witness Statements**: Localized third-party perspectives.
- **Investigation Diaries**: Procedural logs tied directly to timeline events.

### 2.5 Media Asset Simulation
High-fidelity synthetic media generated for forensic and visual analytics modules:
- AI-Generated face profiles for victims, accused, and personnel.
- Mock Vehicle images mapped to registered owners.
- Synthetic Forensic Science Laboratory (FSL) reports.
- Full `reportlab`-generated A4 PDF FIR documents.
- Geospatial heatmap overlays.

## 3. Machine Learning Capabilities

The simulation automatically computes predictive indicators and surfaces them for supervised model training.

### AI Ground Truth Labels
All relevant entity rows include Boolean ground-truth targets such as:
- `label_is_solved`
- `label_is_gang_related`
- `label_is_cyber`
- `label_repeat_offender`

### Explainability Metadata
To support Explainable AI (XAI) models, computed scores (such as Violence Risk or Flight Risk) include an `explainability_metadata` JSON payload. Example payload:
```json
{
  "severity_reasoning": "Heinous Crime (Murder)",
  "time_factor": "Night Crime (02:00 AM)",
  "location_factor": "Occurred at Ward 15"
}
```

### Pre-packaged ML Datasets (`.parquet`)
Upon generation, the platform slices and joins data into specific `.parquet` formats ready for direct `scikit-learn` or `XGBoost` ingestion:
- `risk_prediction.parquet`: For predicting the violence/flight risk of suspects.
- `hotspot_detection.parquet`: Cleaned spatio-temporal datasets for predictive policing models.
- `gang_detection.parquet`: Aggregated network metrics and repeat-offender flags for organized crime modeling.

## 4. Usage

To generate the dataset from scratch:

```bash
# Generate the full dataset end-to-end
python cli.py generate all

# View generation statistics and Dataset Quality Report
python cli.py stats
```

Outputs will be saved in the `output/` directory, organized neatly into `csv/`, `json/`, `training/`, `media/`, and `reports/` folders.

---

## 5. Validation Suite

Before promoting the dataset to production, run the built-in three-stage validation suite.

### Full Validation (Recommended)

```bash
# Runs all three checks in sequence (skip scale for quick audits)
python cli.py validate all --skip-scale

# Full scale test + integrity + dashboard
python cli.py validate all
```

### Individual Checks

#### 1. Scale Test
Runs the generator at multiple case sizes and records generation time, peak memory usage, image count, and graph edge density.

```bash
python cli.py validate scale --sizes "1000,10000,100000"
```

Outputs: `output/scale_tests/scale_test_report.json`

| Metric | Recorded |
|---|---|
| Generation Time | seconds |
| Peak Memory Usage | MB |
| Image Count | count |
| Neo4j Edge Count | count |
| Validation Failures | count |

#### 2. Data Integrity Audit
Automatically verifies all relational and semantic invariants:

```bash
python cli.py validate integrity --output output/
```

Outputs: `output/reports/integrity_report.md` + `integrity_report.json`

| Check | Description |
|---|---|
| Foreign Key Resolution | Every accused, victim, and complainant maps to a real person and case |
| Timeline Chronology | Crime events are strictly ordered within each case |
| Graph Edge Validity | All Knowledge Graph edges have non-null source and target |
| Narrative Consistency | Every narrative document maps to a registered case |
| Media Asset Coverage | Every image has a corresponding metadata record |
| Parquet Schema Compliance | AI training datasets contain all required ML-target columns |

#### 3. Dashboard Readiness Audit
Verifies that every planned visualization panel in Prahari AI has all the tables and columns it requires:

```bash
python cli.py validate dashboard --output output/
```

Outputs: `output/reports/dashboard_readiness_report.md` + `dashboard_readiness_report.json`

Panels audited:

| Panel | Data Sources |
|---|---|
| District Heatmaps | `cases` (lat/lon, district) |
| Police Station Drill-Down | `cases`, `employees` |
| Crime Timelines | `crime_events`, `cases` |
| Network Graph / Link Analysis | `accused_records`, `knowledge_graph_edges`, `call_detail_records` |
| Sankey Diagrams | `court_proceedings`, `chargesheet_details` |
| Repeat Offender Dashboard | `accused_records`, `modus_operandi_records` |
| Risk Score Dashboard | `modus_operandi_records`, `cases` (XAI payload) |
| Investigation Timelines | `investigation_diaries` |
| Explainability Panels | `cases` (explainability_metadata column) |
| Gang Intelligence Dashboard | `gangs`, `financial_transactions` |
| Cyber Fraud Analytics | `cases`, `financial_transactions`, `call_detail_records` |
| AI Training Datasets | `cases`, `accused_records` (all label columns) |
